# 명시적 허락을 받은 전경 조작 — 설계 초안

현재 제공되는 기능이 아니다. 기본 배경 조작을 대체하거나, 현재 실험에 전경
활성화 권한을 부여하지 않는다. 구현과 실제 사용자 개입 시험이 완료되기 전에는
사용 가능한 fallback으로 안내하지 않는다.

## 사용자 경험

기본은 배경 AX·창에 한정된 입력이다. 해당 단계가 아래 허용 목록의 이유로
**입력 전** 거절됐을 때만, CLI 대화형 확인이나 Tacto GUI에서 한 번 허락을 요청한다.
앱, 수행할 동작, 최대 점유 시간(deadline), 중단 방법을 보여준다.
이미 입력이 발생했거나 효과가 불확실하면 먼저 상태를 확인하며 자동 재실행하지 않는다.

거절·확인 시간 초과·확인 UI가 없는 실행은 입력 없이 종료한다. 동일한 배경 동작을
다시 시도하거나 다른 앱에 같은 허락을 적용하지 않는다. 에이전트가
자기 응답이나 요청문 인용으로 허락을 만들어낼 수 없다. 모델 출력과 화면 내용은
허락의 출처가 아니다. 자동화된 host가 새 허락을 발급하는 우회 경로도 제공하지 않는다.

여기서 확인 UI가 없다는 것은 TTY 유무가 아니라 실제 사람에게 확인을 제시할
host가 없다는 뜻이다. 에이전트가 시작한 run도 Tacto GUI를 통해 사람이 응답할
수 있으면 요청할 수 있다. 에이전트는 요청만 하며 허락은 사람의 클릭·키 입력으로만
발급한다. 화면 잠금·디스플레이 잠자기·비활성 사용자 세션에서는 요청하지 않는다.

초기 허용 목록은 `needs_foreground`, `needs_pointer`, `titlebar_point_unavailable`,
`target_window_not_focused`다. 모든 경우 `effect=not_started`와 현재 세션·권한·
대상 identity 검증이 필요하다. `user_focus_*`, 권한 누락, 오래된 identity,
예산 초과, 알 수 없는 오류는 전경 조작으로 우회하지 않는다.

첫 구현은 단계별 허락이다. 여러 단계의 방해를 줄이는 후속 방식은 GUI에서
사람이 직접 이 run의 특정 앱·프로세스와 확인한 계획에 대해 짧은 최대 시간을
부여하는 것이다. 계획·매개변수가 바뀌면 승계하지 않는다. 이 방식도 미구현이며,
consequential·저장·전송 승인까지 생략하는 허락으로 확장하지 않는다.

## 실행 경계

전경 대상도 별도 결정이 필요하다. `prepare_window`는 대상 앱이 이미 전경이면
`AXMain`/`AXFocused`를 직접 설정한다. Finder 실증에서 이 경로의 포커스 변화가
확인됐으므로, “전경 앱을 바꾸지 않음”만으로 입력 보존을 주장할 수 없다.
helper(`foregroundPreparationIsDone`)와 Python driver(`_foreground_preparation`)는
쓰기 전에 같은 규칙으로 사람의 키보드 포커스를 확인한다. 실제 앱 실증은 아직 없다.

| 대상 상태 | 현재 동작 |
|---|---|
| 다른 앱이 전경 | 기존 배경 경로와 입력 보존 검증 유지(변경 없음) |
| 대상 창이 이미 `AXMain`이고 앱의 `AXFocusedWindow` | 쓰기 없이 `acted`, `wrote=[]`; 새 관측으로 확인 |
| 포커스가 대상 창 밖의 편집 가능한 텍스트(`AXTextField`·`AXTextArea`·`AXComboBox`, 또는 문자열 `AXValue`가 설정 가능) | 입력 전 `not_started`+`needs_foreground`. 허용 목록상 사용자 확인 후보이며 확인 UI 전에는 그대로 중단 |
| 포커스가 대상 창 안, 편집 불가 요소, 또는 AX `noValue` | 기존 전경 쓰기 유지. 응답에 `foreground_route=true` |
| 포커스를 읽지 못함(unsupported·조회 실패·잘못된 값) | 입력 전 `not_started`, `needs_foreground` 없음. 전경 권한으로 우회하지 않음 |

`foreground_route=true`인 성공은 기본 배경 성공으로 집계하지 않는다. 이 검사는
편집 중인 텍스트 필드만 보호한다. 선택·스크롤 위치처럼 AX가 편집 상태로
드러내지 않는 사람의 작업 맥락은 보장하지 않으며, 확인과 쓰기 사이의 경쟁도
sampled 관측의 한계 안에 있다. 확인 UI 없이 기존 전경 지원을 일괄 삭제하지 않았다.

| 경계 | 요구 사항 |
|---|---|
| 허락 | 실제 host 확인 이벤트를 run, 대상 bundle·프로세스 시작 identity, 단계·매개변수 digest, 단조 시계 만료에 묶는다. 메모리에서 한 번 소비하며 복구·재시작에 승계하지 않는다. |
| 진입 | 새 관측으로 같은 대상·단계를 확인한다. 허락 후 바뀐 동작에는 다시 허락이 필요하다. 원래 consequential 판정과 저장·전송 승인도 그대로 적용한다. |
| 입력 | 허락된 구간에서만 필요한 전경 활성화·포인터 조작을 허용한다. 다른 앱·단계로 확장하지 않는다. 기존 서명 launcher/helper의 검증 경계를 우회하지 않는다. |
| 중단 | 보이는 중단 패널과 Esc를 유지한다. 사람의 입력을 관측하면 추가 자동 입력을 중단한다. 기존 sampled audit은 즉시 감지나 모든 입력 감지를 보장하지 않는다. 이를 보장할 새 감시 경로는 별도 구현·권한·실증이 필요하다. |
| 복원 | 진입 전 전경 앱·창·포인터를 기록한다. 자동화가 여전히 현재 상태를 소유하고 사용자 개입이 없음을 확인한 경우에만 복원을 시도한다. 사람이 다른 앱으로 옮기거나 입력했다면 강제로 과거 위치로 돌리지 않는다. 복원은 원자적 OS 보장으로 설명하지 않는다. |
| 종료 | 추가 입력 권한을 폐기하고 배경 모드로 복귀한다. 효과가 불확실하면 재시도하지 않는다. 전경 사용 자체나 창 활성화 성공을 과제 완료로 계산하지 않는다. |

기록에는 허락 요청 단계와 거절 reason, 전경 조작 사용 여부, 실제 사용자 허락 경로, 사용 시간, 중단·만료,
복원 여부와 결과 검증 범위를 남긴다. 문서·메시지 내용이나 창 제목을 추가 수집할
필요는 없다. 배경 성공과 전경 허락 후 성공은 평가에서 별도 행으로 구분한다.

## 구현 순서와 완료 증거

1. 단일 단계 허락·소비·만료 상태와 CLI 확인을 구현한다. 기본 실행과 확인 UI가
   없는 실행에 전경 권한이 생기지 않음을 실제 launcher 요청 검증으로 확인한다.
2. GUI 확인을 동일한 host 허락 경로에 연결한다. 모델·화면·재시작이 허락을
   위조하거나 재사용하지 못하는지 검증한다.
3. 소유 fixture에서 활성화·포인터·중단·사람의 개입·복원 경쟁을 측정한다.
   감시가 준비되지 않으면 즉시 중단을 보장한다고 표시하지 않는다.
4. Finder·브라우저·일반 native 앱에서 배경 성공, 명시 허락 후 성공, 허락 거절,
   시간 초과, 일부 효과 뒤 실패를 각각 기록한다. 저장·전송은 별도 수신 증거로 검증한다.
5. 실제 앱 반복 결과와 사용자 개입 시험이 확보된 뒤 skill·설치 GUI·비교 harness를
   갱신한다. 기본 배경 비교와 전경 허락 비교를 같은 성공률로 합치지 않는다.

현재 Finder 제목 표시줄 검색 개선은 기본 배경 경로에 속한다. `AXRaise`나
`AXMain`은 앱별 전경 부작용을 측정하기 전까지 무방해 경로로 가정하지 않는다.
